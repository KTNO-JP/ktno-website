# HP制作標準手順

## 目的・基本方針
企画・素材 → デザイン確定 → GitHub → Netlify自動デプロイ → 実ブラウザ確認 → 独自ドメイン → SEO/Search Console → 運用を一元化する。
2026-10-03保存のHP制作標準手順を基に、KTNOの作業ルールを補足。
GitHubを元データ・変更履歴の基準とし、案件ごとにリポジトリを分ける。確定済みのデザイン・文章・構成を無断変更しない。更新前のコミットと正常Deployを記録する。
運用アカウントのメールは added.tech20000@gmail.com。ログイン、本人認証、最終権限承認、決済は本人へ引き継ぎ、その他の工程は連続して進める。

## 1. 素材・要件
既存サイト、写真、ロゴ、文章、連絡先、Googleマップ、LINE、SNS、掲載許可を確認。PC・タブレット・スマホを前提に構成を確定。案件固有の素材と認証情報を混在させない。

## 2. 制作とGitHub
案件リポジトリをスターターから複製。設定・CSS・JS・素材を差し替え、build/checkを実行。変更内容をコミットしmainへ反映。GitHub Actionsの検査結果を確認する。TenkaHita/tenka-websiteはこの初期投入で変更しない。

## 3. Netlify自動公開
対象GitHubリポジトリのmainをNetlifyへ接続。Build/Publish設定はnetlify.tomlを使用。自動デプロイを有効にし、コミットSHA・Deploy ID・公開URLを照合。Deploy成功だけでは完了扱いにしない。

## 4. 実ブラウザ確認
PC・タブレット・スマホの表示、横スクロール、文字切れ、画像抜け、JSエラー、HTTP応答を確認。電話・地図・LINE・SNS・内部外部リンク、メニュー、キーボード操作を実行。フォーム利用時は受信・通知まで確認。

## 5. 独自ドメイン
Netlifyへドメインを追加し、表示されたDNS値を設定。メール用レコードを保全。HTTPSと主要ドメインへのリダイレクトを確認。SITE_URLを最終URLへ設定して再デプロイする。

## 6. SEO
title・description・canonical・OGP・必要な構造化データ・画像alt・内部リンク・robots.txt・sitemap.xmlを確認。プレビューはnoindex、本番は情報確定後にindexingEnabledを有効化する。本文・デザインは確定内容を維持する。

## 7. Search Console
所有権確認 → sitemap.xml送信 → URL検査 → インデックス登録リクエスト → Google登録状況確認 → 後日の検索反映確認。公開完了とインデックス完了を分け、Google処理待ちはその状態を記録する。

## 8. 完了条件
最新版がGitHubへ反映／Deploy成功／公開URL正常／3端末表示確認／画像・主要導線確認／独自ドメイン・HTTPS確認／SEO設定確認／Search Console実施または待ち状態明記／更新履歴記録。
詳細は公開前後チェック.mdを案件ごとに複製して記入する。

## 9. Record & Replay
利用可能な繰り返し操作を記録・再利用。パスワードや認証コードを記録しない。再実行前にアカウント・サイト・入力内容を確認。ファーマゲート・天花など案件ごとに分離。再実行後は結果と公開URLを確認する。

## 10. 保守・改善
公開状態、リンク切れ、表示崩れ、修正依頼、GitHub/Deploy履歴、Search Console状況、月次レポート、作業時間と認証回数を記録する。
不具合の症状・原因・修正・再発防止をCHANGELOGへ記録し、共通の改善はKTNO Web Starterへ還元。異常検知とミス防止を標準工程に含め、同じ失敗を繰り返さない。
公開後の定期監視は実際の監視設定を作成してから稼働中と扱う。
